# 配置树图与复习的数据方案 {#configuration}

方案记录“从哪里取数、每列代表什么、怎样筛选”，由工作台配置服务保存。插件包提供字段格式与默认值，实际表名、查询、参数和实例绑定留在当前资料库。以下字段来自当前配置界面；先预览，确认后再保存。帮助与预览不会替你提交草稿。

## 选择或新增方案 {#manage-add}

在章节树图或表格复习的方案页选择新增，进入配置。已有表、自己的数据、高级 SQL 是三种来源方式；先选择最接近需求的一种，再填写必需字段。新增方案与创建复习会话是不同操作。

## 编辑已有方案 {#manage-edit}

先选中目标方案再编辑。核对当前资料库和方案名称，保留需要的原始配置。修改查询或字段绑定本身不改来源表；“自己的数据”模式中明确修改行并保存，才会更新该方案管理的集合。取消保留原方案。

## 方案名称 {#name}

填写容易辨认的名称，例如“章节阅读示例”或“术语复习示例”。名称帮助人选择方案，不代替节点/卡片 ID，也不决定 SQL 查哪张表。保存方案不会自动开始复习。

## 数据来源 {#source}

- 已有表：选当前可读的表，通过字段映射适配，不复制来源表。
- 自己的数据：在编辑器填写节点或卡片；只有明确保存才创建或更新独立集合。
- 高级 SQL：用只读查询表达筛选或关联，适合了解字段和参数的维护者。

切换方式后重新核对字段和预览结果，不能将之前方式的成功预览当成当前配置已验证。

## 字段映射 {#mapping}

将实际列对应到插件需要的角色。树图需要稳定唯一的节点 ID、父节点 ID 和标题；复习需要稳定唯一的卡片 ID、问题、答案。各角色使用不同的列。映射负责解释列的含义，不重命名数据库字段。

例如只读示例行 `{ "id": "n2", "parent": "n1", "label": "示例子节点" }` 中，节点 ID 映射到 `id`，父节点映射到 `parent`，标题映射到 `label`。先确认查询还返回了 `n1`，再执行校验。

## 自己的数据 {#rows}

每行是一张卡片或一个节点。先填必需字段，使用不同且稳定的 ID；根节点的父 ID 留空。删除编辑器中的行只是修改草稿，保存才生效。该方式管理自己的集合，不应被理解为可以编辑任意已有表。

## 节点 ID {#node-id}

节点 ID 是身份，不是排序号。系统可先生成 ID；已被使用后应保留。修改 ID 时同时处理引用它的父关系，否则原节点会变为找不到或缺父节点。重复 ID 需要修正后重新校验。

## 父节点 ID {#parent-id}

根节点留空，子节点填写另一节点的 ID。不能引用自己、后代或不存在的节点。出现环时先检查父关系；改变浏览根只影响视角，不会修复数据中的环。

## 节点标题 {#title}

标题是树上显示的非空名称，长说明放在正文。标题不是 SQL 表达式，重名标题不等于相同节点；身份仍由节点 ID 决定。

## 卡片 ID {#card-id}

卡片 ID 用于关联卡片与到期时间，必须唯一。编辑已有题目时保留 ID；随意换 ID 会让同一内容被识别成新卡片。题目文字相同不能代替 ID 校验。

## 问题 {#question}

问题是显示答案前看到的非空提示，可用纯文本或 Markdown。写成无需看答案也能独立理解的问题。预览确认实际文字和格式后再保存，预览不会产生评分。

## 答案或正文 {#answer}

在复习中作为答案，在树图中作为详情正文。支持文本、段落、列表与 Markdown；保存的代码示例是文字，不是执行命令。空正文节点不应产生可展开的空白详情。

## 独立复习间隔 {#intervals}

自己的复习集合使用四个正数天数，对应“不记得、困难、良好、简单”，例如 `1、3、7、14`。实际评分才更新到期时间，编辑题目保留已有到期时间。该设置不意味着所有既有复习方案都使用相同调度规则。

## 高级 SQL {#sql}

只允许查询，不在此使用 CREATE、UPDATE、DELETE。树图查询返回节点和父关系，复习查询返回 `card_id`、`question`、`answer` 所需角色。按 Tab 可缩进。查询成功仍需执行字段和关系校验；只拿到部分结果时不能把完整性检查当作成功。

## 默认参数 {#parameters}

`:名称` 对应同名 JSON 参数。示例 `{ "node_id": null }` 表达一个未限定的节点选择，具体含义由该方案查询决定；不用参数时为 `{}`。这是参数值，不是把用户输入拼接进 SQL 的文本模板。可视化方式会处理所需参数。

## 高级模块设置 {#settings}

包含字段映射、详情模块和复习调度等结构。可视化方式会生成相应部分；手工修改前阅读该模块字段合同。格式正确不代表业务绑定正确，修改后重新校验。实际配置保存在当前工作台，不写回通用插件 ZIP。

## 校验与预览 {#preview}

检查角色是否齐全、ID 是否重复、父节点是否缺失及树关系是否有环。预览不建表、不保存、不评分。结果过多而校验无法覆盖时，缩小查询或按错误提示处理，不能忽略警告直接认定数据正确。

## 保存方案与数据 {#save}

已有表和 SQL 方式保存查询方案，来源表保持原内容；自己的数据方式明确创建或更新集合并保存方案。保存失败时保留草稿，先读错误与服务器状态再重试，避免通过反复新增绕过冲突。保存完成后回到方案页重新预览，开始复习仍需要单独确认。

## 常见故障与下一步 {#troubleshooting}

字段缺失先检查来源和映射；卡片集合不对先检查参数和根节点；树无法显示先检查唯一 ID、父引用和环。保存后打开的是旧会话时，应按[复习说明](plugins.md#review)区分恢复与新建。界面帮助无法定位时，先聚焦目标字段再点击问号；完整说明在帮助阅读器中打开，不提交配置。
