# 章节树图增量更新计划

## 目标

减少新增、编辑和删除节点后的等待时间，使界面先显示已确认的局部结果，再在后台校验完整树；同时继续使用服务端 `study_knowledge_edit` 日志和 `request_id` 保证撤销、重做与幂等。

## 现状与原因

当前保存成功后，前端还会重新请求完整的 `/api/study/tree?model=knowledge`，再销毁并重建整棵树。树数据规模较大时，这个响应会达到数 MB，移动端等待主要发生在这一步。服务端保存本身还会生成历史差量并重建树，不能把“保存成功”误认为“树刷新完成”。

## 分阶段方案

### 阶段一：局部确认后立即更新（本次实施）

- 使用保存接口返回的节点更新本地树，不再把完整树请求放在用户可见操作的关键路径上。
- 新增和编辑后立即重绘当前视图；删除后立即移除节点，`self` 删除时提升子节点，`recursive` 删除时移除整个子树。
- 完整树请求改为后台校验，校验失败只提示用户并保留“刷新”入口。
- 保留原有服务端版本检查、幂等请求 ID、撤销和重做日志。

### 阶段二：乐观更新（后续）

- 保存请求发出前显示临时节点或临时删除状态。
- 请求成功后用正式节点 ID 替换临时 ID；失败时按快照回滚。
- 为待同步操作增加状态标记，避免网络中断时误认为已保存。

### 阶段三：增量接口（后续）

- 增加按根节点或子树读取的接口。
- 保存接口返回受影响节点、父子关系和树版本号。
- 前端只刷新受影响子树，不再下载整棵树。

### 阶段四：版本与协作（后续）

- 服务端维护树 revision 和差量缓存。
- 多设备协作时再引入 SSE/WebSocket 变更通知。
- 版本冲突时保留当前本地视图，并提示用户重新合并。

## 验收标准

- 新增、编辑、删除成功后，当前视图先出现局部结果。
- 后台校验不会覆盖用户随后进行的另一项编辑。
- 删除 `self`、删除 `recursive`、撤销和重做的父子关系正确。
- 网络错误或版本冲突不会丢失本地视图，也不会产生重复服务端记录。
- Android runtime 与网页源文件保持一致，APK 构建通过。
