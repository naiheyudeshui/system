# 第一版学习库迁移到第二版

第二版 Android 使用独立应用标识 `local.studykb.contractv2`、端口 `18033`，可与第一版并存。当前个人安装包版本为 `2.0.2-contract-v2`。它是个人数据交付物，不能作为公开下载包发布。

## 数据迁移约定

1. 手机第一版只读导出 SQLite 一致性快照，保留源文件和 SHA-256。目标库另外保存 SQLite 和含附件的整库 ZIP；不直接覆盖目标库。
2. `tools/study_library_merge.py` 只对新文件合并。必须显式指定 `--source-is-primary`。统一知识 ID、父子关系、复习调度、评分和会话继续使用原 ID；目标存在独立知识编辑或不可判断的评分冲突时中止。
3. 知识修订以确认的手机主库为准；较新计时状态保留；第二版插件、附件、布局和已修复的 SQL 配置保留。变更前后记录保存在 `study_library_merge_revision`，不复制出另一套同名卡片。
4. `--purge-archived-deletions` 只清理能从实际删除历史或其后代确认的 archived 知识行。暂停学习的 suspended 节点不会被当作删除。找不到删除依据的归档记录保留并计数。
5. 在独占维护期间，对最新目标重新备份和合并，校验全部有效源知识逐行一致、无树环、无断裂外键、每张卡都有调度，验证附件原件后再写入当前库。镜像和 ZIP、APK 均不提交 Git。

2026-10-31 批次：源库 1,436 条知识，其中 967 条有效；469 条确认的旧删除记录已物理清理，另清理 367 条关联调度和 7 条关联评分。结果保留 967 条有效知识、821 张卡、352 条当前评分、62 次复习会话，以及原有附件和第二版配置。被删除内容的恢复依据保留在备份与操作历史，不作为隐藏知识行继续参与查询。

## 树图删除语义

- 仅删除自身：从 `study_knowledge_item` 真正删除该行，子节点上移到原父级。
- 递归删除：真正删除节点及全部后代。关联调度、评分和以已删除节点为根的 scope 一起移除。
- 撤销：操作历史保存完整恢复快照，恢复原 ID、调度、评分和 scope。历史快照不属于可学习知识行。修改正文不会生成另一份 archived 知识；新建操作的撤销也物理删除新行。
- 撤销/重做检查并发修改。子节点已有新编辑、恢复后产生新评分或新增后代时，拒绝覆盖。
- 文件引用在同一事务更新。删除知识不强制销毁共享图片/PDF 原件；撤销历史或其他插件仍可能使用该文件，物理文件 GC 继续关闭。
- 旧复习会话保留当时的题目快照。已删除知识不能在这些旧会话中继续评分，应结束旧轮次、从当前知识重新预览开始。

## APK 怎样携带完整数据

普通构建继续拒绝“只有附件索引、没有文件原件”的 seed。个人构建可显式设置 `STUDY_APK_LIBRARY_BUNDLE`，指向已验证的完整 Study library ZIP；其数据库和全部原件一起进入个人 APK。

构建校验 ZIP 清单、逐文件哈希、库身份、数据库完整性和全部附件元数据。插件权限仅从实际随 APK 打包的本地插件描述重新建立，未知插件不自动执行。数据不得放入公共插件包或共享宿主。

首次安装：seed 数据库含一次性 pending 标记；启动前核对整份数据和 ZIP 指纹，先在私有目录准备并验证附件，再原子发布文件根，最后标记完成。失败时不启动一个缺少原件的库，可重试。

升级已有第二版：Android 保留原数据库和私有文件根，APK 不覆盖。新 seed 只用于新安装，因此已有第二版需要显式导入最新完整 ZIP 才会取得本批合并数据；应先导出当前数据，不用卸载/清除数据作为迁移方法。

验证包括虚构库合并、删除/撤销/重做、评分及附件恢复、ZIP 损坏拒绝、首次启动重试和已有安装不覆盖。桌面上的 Android runtime 启动检查与 APK 签名检查不等于 Android 真机验收。
