## 知识交互完整使用指南

> 面向使用者，按 2026-09-19 的源码和接口编写。先读第 1–3 节理解与浏览，再按第 4–6 节整理、背诵；第 7–9 节说明维护与排错。本文不要求你手写 SQL 或直接操作数据库。
>
> 本仓库 `readme/` 是 `D:\Rsim_helper\readme` 的软链接，因此项目专用的“给人读的说明”直接放在这个 **system 根 README.md**，不修改共享文档池。Agent 执行细节见 [Agent 手册](.cursor/skills/study/SKILL.md)。

### 1. 用一分钟理解：先找位置，再背知识

把知识库想成一个带复习提醒的书架：

- **章节树/知识图是书架目录**：书、章、节、知识点，回答“这个知识放在哪里”。
- **知识详情是讲解页**：点击一个知识点，右侧显示它的 Markdown 正文。
- **卡片是自测题**：正面问题、背面答案，回答“我能不能独立想起来”。
- **复习时间是提醒**：根据你的评分安排卡片下次出现的时间，不是给目录评分。

例子：你说“把这页里两个容易混淆的概念整理到第三章”。Agent 应先找到已有第三章，给出两个概念的简短问答和比较卡提议。你确认后，它把知识点挂到第三章的合适小节，保存答案和卡片。你在树里找关系，在复习里遮住答案自测；两处用的是同一批内容，不必重复录入。

### 2. 知识图和卡片图到底怎样关联

```text
一本书（目录）
└─ 某一章（目录）
   └─ 某一节（目录）
      ├─ 什么是概念 A？（知识点）── 卡 A：问题/答案/复习时间
      ├─ 什么是概念 B？（知识点）── 卡 B：问题/答案/复习时间
      └─ A 与 B 如何区分？（知识点）── 比较卡：问题/答案/复习时间
```

**它们不是两套互不相干的图数据库。** 知识树保存节点的父子关系，卡片保存“属于哪个节点”。视图只是把相同数据换一种方式展示。

| 界面概念 | 你需要理解的意思 | 数据对应 |
| --- | --- | --- |
| 目录节点 | 帮你分类，不必有问答 | `study_node`，role=outline |
| 知识点节点 | 有具体问题和讲解 | `study_node`，role=topic，正文为 answer_md |
| 卡片 | 一次可评分的问答 | `study_card`，通过 node_id 归属节点 |
| 卡片答案 | 这张卡自己的答案 | `study_card.back` |
| 学习视角 | 只看某一本书/章/节及其后代 | `study_scope` 指向一个节点 |
| 复习方案 | 决定选哪些卡、按什么顺序复习 | 保存的 SQL 查询与参数，不是卡片本身 |

推荐“一知识点一节点一卡”，清楚好维护；但系统**允许一个节点有多张卡**，不是强制一对一。多卡节点有公共讲解，各张卡又各有答案；不能把公共讲解当成每张卡都相同的答案。

切换学习视角只是缩小观看范围，不会复制、删除或移动知识。相同书名可能对应不同导入记录；让 Agent 根据节点 ID 和完整路径辨认，别只说“随便找一个同名节点”。

**所有知识都是节点：** 章节与活跃卡片统一进入候选表格和树图，每个节点都有标题和可空的 Markdown 内容。卡片标题来自 front，正文来自 back；不需要为显示卡片另建知识点。节点方框左侧显示完整标题并自动换行，右侧为操作区。子树默认收起，点击右侧＋展开、−收起；点击标题选中节点后出现正文下拉按钮，无内容时禁用。需要进入详情子页时点击工具栏“节点详情”。拖动空白可大范围移动，迷失位置时点“适应画布”。

### 3. 打开前端，找到和读懂知识

#### 启动

在 system 项目目录打开终端：

```powershell
python study-kb/tools/serve_workbench.py --port 8033
```

浏览器打开 `http://127.0.0.1:8033`；或者使用 `study-kb/打开学习库.bat`。终端里的服务需保持运行。默认数据在 `study-kb/data/study.sqlite`，不要误开 Studio 的 `ops.sqlite`。首次使用还需 Python 环境及可用的 `3dStudio/` 共享宿主链接。

改了服务代码需要重启服务；只新增知识通常刷新页面/树即可。仍显示旧界面时按 `Ctrl+F5`。新版树图采用本地原生 SVG；Markdown 的部分前端依赖仍来自 CDN，离线或网络拦截时不保证首次加载成功。

#### 当前界面地图

| 区域 | 用法 |
| --- | --- |
| 顶栏 | 表格、章节树图、表格复习等工作区标签；只替换中间区域 |
| 左侧 | 选择数据表/视图，便于核对卡、目录和到期信息 |
| 中间 | 当前表格、树图或复习工作区 |
| 固定指标区 | 显示摘要，沿用原设置方式，不在插件管理里 |
| 下栏 | 字段说明、SQL、唯一的插件管理入口及放到下栏的插件 |

插件位置可能已被你拖动修改，因此不一定都在顶栏。到下栏“插件管理”找：左上是顶栏启用，右上是下栏启用，下面是未启用。在同一框内拖拽排序，跨框拖拽换位置/启停。没有位置下拉框或前移按钮；停用插件不删除知识与复习历史。

#### 阅读一章

1. 点击“章节树图”。
2. 选择“学习知识树”或已保存的 SQL 方案卡。前者保留学习视角选择与关联卡片；后者可映射任何合适查询结果的节点、父节点、标题和多个详情列。
3. 点“预览并筛选”：先显示结构校验结果（单树/森林、根数量、最大深度、警告），再显示完整候选表格。点击列头筛选；筛中子节点会自动保留祖先，并显示补充数量，避免凭空断开关系。
4. 可搜索并指定一个“根节点”，再点“打开树图”。图占满中间工作区，可拖动画布，使用右上缩放/适应画布按钮。
5. 右上“刷新”重新读取数据并保留筛选条件；“大纲”将整个树图页切换为大纲页，再点“树图”切回，不再显示两套并排视图。
6. 点任意节点进入详情子页面，查看多个 Markdown/纯文本模块；系统学习树还显示直属卡片的独立答案。“返回树页面”保留根、模式和当前树；“以此节点为根”进入该子树，“恢复全图”恢复当前筛选集合。
7. 需要修改数据解释方式：返回方案，设置 → 编辑已有方案/新增方案，填写只读 SQL、节点/父节点/标题列和详情模块。保存会执行结构校验。这里只编辑方案，不直接修改知识正文或数据库父子关系。

### 4. 每个节点下的知识能否使用 Markdown

**可以。** 节点详情保存 Markdown，卡片答案也可用 Markdown。适合用结论、清单、小表格和例子把知识写得好读、好背。原始 HTML 会被安全清理，不支持任意脚本或样式表注入；Markdown 排版不等于给节点自定义 CSS。

一张知识卡的推荐结构如下。内容是自编操作示例，不是教材事实：

```markdown
**一句话结论**：目录告诉你知识在哪里，复习提醒告诉你什么时候再练。

**关键区别**
| 维度 | 目录 | 提醒 |
| --- | --- | --- |
| 关注的问题 | 放在哪里 | 什么时候复习 |
| 主要操作 | 分类、展开、移动 | 回答、评分、看下次到期 |

**通俗例子**：书架分类帮你找书，借阅单日期提醒你还书。

**易错点**：移动知识点的位置，不代表应当清空它的复习历史。

**来源**：本指南自编示例。
```

常用粗体、列表、表格、引用和代码块可以使用。不要依赖复杂公式、Mermaid 图或本地图片路径自动渲染；有需求先让 Agent 检查前端能力。

**给 Agent 资料时不用记所有语法，但要分清两件事：** 正文里的小标题是讲解；大纲文件里的 `#` 标题可能被导入成新树节点。现有大纲导入器不是完整 Markdown 文档导入器，会丢弃空行，也可能把代码中的标题误当节点。复杂正文应让 Agent 使用 JSON/helper 写入，不能直接把任意 Markdown 笔记当目录导入。

### 5. 怎样请 Agent 整理资料并插入已有库

#### 最好交代这些内容

- **材料**：文件/图片/笔记/粘贴文字，尽量给版本、章/节/页码。
- **位置**：已有哪本书、哪一章/节；允许 Agent 先查真实节点 ID。
- **目的**：背定义、比较易混点、准备论述题，还是理解流程。
- **颗粒度**：喜欢短答还是较详细解释；哪些原文术语必须保留。
- **权限**：先出草稿，还是按之前已确认草稿执行；是否允许改旧卡/移动树。

可直接发送的命令示例：

> 阅读 `.cursor/skills/study/SKILL.md`（已含完整操作手册）。把我提供的第 3 章笔记整理成通俗、可背诵的知识卡，先检查已有第三章与重复内容。每张卡一个明确问题，答案包含一句话结论、关键点、例子和来源。先给目录差异和问答草稿，不要入库。

确认后：

> 按刚才确认的草稿，插入已查到的第三章节点下。复用已有知识点，不重建整本书，不重置旧卡复习记录。完成后告诉我新增/修改的节点和卡片数量、所在路径以及怎么在前端找到它们。

改写旧卡：

> 这张卡太长，请保留知识含义和来源，改成能直接回忆的简短答案；补充的解释放后面。先告诉我是否应拆卡，确认后再更新已有 ID，保留复习历史。

补充细节：

> 在这个知识点详情里补一个 Markdown 比较表和易错点。如果不增加独立考点，先不要额外生成卡片；请确认节点答案与单卡答案是否要同步。

维护树：

> 把这些知识点移动到已有“概念比较”小节，先展示新旧路径与受影响卡片，不删除重建，也不要改变复习记录。

#### 什么样的草稿值得确认

- 一看问题就知道要回忆什么，不是“这个有哪些特点”之类缺上下文的问题。
- 答案有短结论，不是整页 OCR；必要条件和例外没有被“通俗化”删掉。
- 多个知识点按主题挂树，而不是全堆在父章节的一张长卡里。
- 有来源；无法辨认或有争议的句子标为待核实，不假装已经核对。
- 写清哪些是新增、哪些是修改、哪些会移动；不会悄悄删旧卡。

#### 完成后应该得到什么

Agent 应返回：资料范围、目标树路径、节点/卡 ID、新增与修改数量、来源、查重与关系验证、历史是否保留、审计位置，以及具体前端路径。只有 Markdown 文件没有数据库写入时，应明确写“草稿，未入库”。

### 6. 从“看懂”到“能背”：使用表格复习

1. 打开“表格复习”。
2. 点击已有方案方框，选中后出现“预览并筛选”和“开始一轮学习”：**章节卡片**包含选定范围内未到期的卡，适合刚整理完先学；**今日到期**取当前已到期的卡（包括逾期）。
3. 不再单独设置“章节范围（含后代）”。章节归属统一在预览表格的“章节路径”等列筛选；已有 SQL 方案自身的条件和默认参数仍然生效。
4. 点击“预览并筛选”或“开始一轮学习”进入全量候选表格（分页浏览）。点击列标题搜索/选择并应用条件，可按问题、章节路径等进一步筛选；多个列条件共同生效。缺少调度等异常让 Agent 排查，不为凑数创建重复卡。
5. 确认筛选数量和本轮上限后，在预览页点击“开始一轮学习”才进入学习。先回忆问题，再“显示答案”，然后根据真实回忆效果评分；零条不能开始。若提示数据已变化，返回方案重新预览。
6. 1=重来，2=困难，3=良好，4=简单。评分更新这张卡的下次复习时间；仅打开答案或未完成本轮不等于所有卡都已复习。

开始一轮后，题目集合和方案版本已固定。你中途修改查询/新增卡，不会自动混入已开始的这一轮；需要结束/离开后开始新一轮使用新集合。保存的会话可恢复，最近会话入口与浏览器状态也有关；换浏览器不应假定自动找回同一入口。

**管理方案不是编辑知识内容。** 复习页右上设置按钮显示顶部的管理方格，左右各半分别为“编辑已有方案”和“新增方案”；编辑打开当前选中的方案。编辑页可保存、复制、预览、删除和恢复查询配置；“返回”回业务界面。上次学习进度通过“继续上次复习”打开，不再自动混在方案选择下面。编辑查询只是改变“选什么、怎么排”，不会自动写入新知识点。普通用户选已有方案即可，复杂 SQL 交给 Agent 按实际契约配置。

进一步配置见 [工作区与 SQL 方案说明](study-kb/docs/WORKBENCH-UPGRADE.md)；[复习协议说明](study-kb/docs/REVIEW.md)也包含旧版本兼容内容。

### 7. 日常维护，避免重复和学习记录丢失

- **不要重复整书导入当更新**：当前整书导入会创建新根，不按标题合并。同一材料修订应让 Agent 按已有 ID 更新或增量添加。
- **不要随便删目录**：数据库存在级联关系，删父节点可能把子树、卡片、scope、复习状态和日志一起影响。先确认移动/归档方案。
- **改措辞和换知识点不是一回事**：轻微改写通常原位保留历史；换了知识含义应讨论是否建新卡并归档旧卡。
- **切换视角不是移动知识**；表格选不同视图也不是复制数据。
- **图、卡都要检查**：点节点看说明，点卡看答案；多卡节点不能只检查父答案。
- **备份是真正的数据保护**：Git 主要保存代码/说明，默认本地 SQLite 不入 Git。让 Agent 使用 SQLite backup 做一致性备份；恢复备份会覆盖备份之后的活动，先确认。
- **来源与审计要留**：来源方便纠错，导入记录帮助找到本批新增内容，而不是日后只能靠标题猜。

### 8. 常见问题

| 看到的问题 | 先检查什么 | 应怎样处理 |
| --- | --- | --- |
| 新知识在图上找不到 | 当前 scope、是否选了 SQL 树、是否刷新 | 回默认树选择正确书/章，再按交付 ID 查询 |
| 卡片存在但图上没有节点 | scope、筛选、卡状态或旧自定义 SQL | 用“学习知识树”或查询 v_study_knowledge_nodes；只查 study_node 的自定义方案仍不会包含卡片 |
| 今日到期没有新卡/某张卡 | 方案参数、状态、调度时间、是否已评分 | 先用章节卡片预览，查调度而不是重新导入 |
| 两张卡答案一样 | 是否错误地把父节点 answer_md 当所有卡 back | 让 Agent 逐 card ID 核对；保持各卡答案独立 |
| 树详情没有保存知识正文按钮 | 详情是只读子页面，方案管理只改变查询与映射 | 请 Agent 按已有 ID 修改知识内容，不将编辑 SQL 当作改正文 |
| 多出很多“节点” | 是否把答案的小标题当大纲导入 | 停止重复导入，按批次审计提出修复计划 |
| 重复书名或卡片 | 是否重复执行了追加式脚本 | 用 ID/来源核对，先规划合并，别盲目删除 |
| 树图/Markdown 加载失败 | 服务、控制台错误、CDN 网络 | 重启/强刷并记录错误；不代表库中数据丢失 |
| 不能找到插件入口 | 插件是否停用或被放在另一栏 | 在下栏插件管理通过拖拽启用/定位 |

### 统一节点表格与树图

画布空白处拖拽不会选中节点文字；滚轮向上放大、向下缩小，以鼠标位置为缩放中心。展开的正文仍可选择复制，正文内滚轮用于滚动内容而非缩放画布。

主表格视图选择“知识节点（含卡片）”（`v_study_knowledge_nodes`），可直接看到章节和卡片同列展示：

- `node_id` / `parent_id`：统一节点关系；前缀 `node:` / `card:` 防止两张原表 ID 冲突。
- `title` / `content_md`：节点标题和可空 Markdown 正文；卡片对应 front/back。
- `source_type` / `source_id`：真实记录类型与原 ID；`owner_node_id` 是原章节 ID。
- 默认只包括活跃卡片，不改写、复制或删除原卡片，不改变调度、评分日志或已开始的复习。

“预览并筛选”按标题、内容或其他列筛中某张卡后，会自动保留它的章节祖先。选择“学习知识树”时学习视角仍有效。已有未经编辑的“全部章节”方案已更新为统一查询；自行编辑的 SQL 不覆盖，可改为：

```sql
SELECT * FROM v_study_knowledge_nodes ORDER BY sort_order, title, node_id;
```

这个视图只读。修改资料仍按原节点/卡片 ID 编辑原记录；不要把带前缀的图 ID 写入复习外键。


树图节点样式更新：标题区域加宽至 260px，右侧 48px 为框内操作区；长标题逐行完整显示，节点高度与兄弟间距随内容调整。连线单独绘制在节点底层，不再穿过外置开关。正文已展开时保留收起按钮，便于切换选择后继续操作。


### 在树图中直接新增与编辑

局域网浏览：在服务器运行 `python study-kb/tools/serve_workbench.py --host 0.0.0.0 --port 8033 --no-open`，其他同网设备打开 `http://服务器局域网IP:8033`。默认只监听127.0.0.1，无法远程连接；请先正常停止旧服务再启动。若被Windows防火墙拦截，仅对专用网络的本地子网放行TCP8033，不做公网端口映射。注意这不等于完整的只读安全隔离：现有服务并非所有端点都有统一鉴权，只应向可信局域网开放。节点编辑/复习写接口另要求STUDIO_API_TOKEN及Bearer请求头，目前前端postApi没有令牌输入/发送功能，直接从远程浏览器保存会被拒绝；不要为此移除鉴权。

重启服务并强刷页面后，使用“学习知识树”或未改写的内置“全部章节”统一方案，点击标题选中节点：

| 快捷键 | 操作 |
| --- | --- |
| Tab | 打开新增子主题编辑页 |
| Enter | 打开新增同级主题编辑页，按数据库真实父级创建 |
| Shift+Enter | 编辑标题下面的 Markdown 内容 |
| Escape | 编辑页取消返回，有草稿会确认 |

先填写标题和可空正文，按“保存”才写入数据库。“预览 Markdown”可检查效果；工具栏也有三个同名操作按钮。输入框里的 Enter 仍是换行，Tab/Shift+Tab仍按正常表单焦点操作，节点右侧按钮的 Enter 仍切换开关。

- 新增的是普通主题，不自动加入复习队列。需要背诵卡时再按知识卡流程创建，避免误操作生成复习任务。
- 卡片节点同样可以新增子主题；新增内容记录保存在原章节下，并有独立关系表表达卡片作为图父级，不更改原卡片或复习历史。
- 编辑卡片内容更新 back；编辑章节/主题内容更新 answer_md。不会自动将章节正文同步覆盖某一张关联卡片。
- 保存后自动刷新并展开目标祖先，保留画布缩放和平移。筛选未命中新节点时会临时展示并提示；“同级”不受临时浏览根影响。
- 自定义 SQL 图默认只读，避免将计算列或外部数据写错表。可切换到系统学习树编辑。
- 发生并发修改会拒绝覆盖并保留草稿；可复制草稿后取消并重新打开。网络中断时“重试保存”使用相同请求，不重复创建；“已保存，但树图刷新失败”只需“重新加载树”。

正文底色现在继承整个卡片，铺满到底部并统一裁切圆角，不再显示内层矩形浅色块。
